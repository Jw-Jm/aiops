# ADR-0040：DeepFlow 实时 L4 与 L7 专项开发

日期：2026-10-13。状态：Accepted（用户明确授权）。

用户要求按“完成 2/3 收尾 → DeepFlow L4 → L7”推进。先完成 ADR-0039 的
真实来源与运行机制验收，再补齐实时网络来源身份映射、L4 查询、L7 上下文及
MCP/平台能力展示。模型回答质量不作为本轮验收标准，协议、范围、引用和
来源验证仍必须通过。既有质量失败证据保留。

运行和部署仅在 root@192.168.0.63，使用独立开发 namespace、存储、来源
及测试身份；不使用本机 OrbStack，不修改既有 core/final 发布配置。复用
锁定的 DeepFlow v7.2.0 源码提交 e567b167453ffa99f08f26def20379b4f831e073；
不同架构/镜像构建须记录实际不可变 digest，不能挪用旧镜像的准入证明。
开发部署保持 candidate，不自动进入 core Bundle 或宣称生产兼容性。

实时身份必须结合当前 Kubernetes UID、namespace UID、容器运行身份和
生命周期验证；仅名称、冻结 endpoint 文件或后端 LCUUID 不足以证明实时
身份。查询仅使用固定 Server/Querier 模板、组织 header 与双端范围过滤。
来源撤销、对象重建、超时、字节/行预算和不可解析的端点必须如实拒绝或降级。

L7 通过实际协议采集和范围验证后按来源配置启用，只输出必要的协议、状态、
耗时等 D1 元数据，不输出请求/响应内容、头、SQL、完整 URL 或敏感参数。
Trace 补全仍保持 CAPABILITY_DISABLED，不引入 Jaeger/OTel 套件。

本决定补充 ADR-0006 的 L7 验证条件与实时接入实施；不修改根目录 00～10
正式文档，不恢复 ADR-0008 延期的 KubeVirt/CDI，不授权生产切换或自动修复。
