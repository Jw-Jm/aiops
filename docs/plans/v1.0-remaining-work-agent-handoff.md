这是下一轮第一优先级，主要是联合验证及暴露缺口后的开发，不是新增一套收集器。

3. 建立新的实际采集故障窗，按需要采集基线和恢复窗；冻结 UID、namespace UID、容器身份、来源 revision、覆盖和时间资格。历史缺失继续显示缺口，不能用当前快照补过去。
4. 在已有专属 canary 范围验证非空异常事实、相关证据和正常反证。数值与原始采集记录/独立 oracle 对照，不能调用被测计算器生成黄金值；共享 Node 只读，不制造宿主故障。
5. 先固定收集，再通过独立解释轮次读取**同一批实际已提交结果**；自然语言追问应在冻结身份/窗口内产生本轮新读取，明确“只解释”时不额外采集。检查 Fact/QueryResult/Evidence/来源 Step 引用能从现有页面定位。

本项交付应包括：三类资源逐项状态、至少一个授权范围的五来源实际可用证据、非空调查与解释/追问关联回执、相关真实浏览器记录、未满足的来源资格。先前网络浏览器三轮 PASS 和最近状态 UI Fixture 各有适用范围，不能替代本项的最新联合验证。
