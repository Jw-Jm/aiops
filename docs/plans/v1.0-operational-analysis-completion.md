# V1.0 运行数据关联分析与辅助诊断功能补齐方案

日期：2026-10-15。状态：用户已确认范围；本轮实现与验证状态见 [开发记录](v1.0-operational-analysis-progress.md) 和对应证据，来源资格、中文模型质量与版本验收分别记录。

代码基线：main `53b0b9e91dd32d71d955ec940929952f8434530b`。本次仅保存方案，不构成功能、真实来源、模型质量、版本验收或生产发布通过。

## 1. 目标与已确认取舍

基于现有平台补齐运行数据关联分析、内网大模型辅助研判、异常分析、故障辅助诊断和自然语言交互。用户已确认：

- 独立调查入口支持 Pod、Node、PVC。
- 新增跨源研判由用户按需发起；保留既有后台异常检测，不增加每条异常自动调用模型。
- 连接已有内网 OpenAI-compatible 模型，不开发推理服务、模型权重安装或训练能力。
- 使用固定规则和冻结基线，不增加自适应学习、预测或通用 RCA 框架。
- 至少一个授权范围内，Kubernetes、VictoriaMetrics、VictoriaLogs、DeepFlow、内网模型五条实际链路均须可用。每轮按目标类型和预算选择适用来源，不无差别调用全部来源。
- 首批新增诊断覆盖 Kubernetes 与 HTTP/TCP。既有硬件能力保留，新增硬件诊断作为后期规划。
- 变更来源限定 Kubernetes 与平台实际执行记录；外部 CI/CD、配置发布系统后续接入。
- R3 共同依赖、R4 变更关联、R5 恢复迹象按严格证据资格生效。相关功能必须完整；缺少可靠时间或历史证据时保留明确缺口，不阻断其余 V1.0 能力。
- 网络调查保持同一授权 namespace 内一跳。集群资源须显式选入且授权允许；已有正式 RCA 配方的受限原生关系路径保留。
- 不自动执行命令、改变 Incident 状态或确认正式 RCA。

沿用 [AGENTS.md](../../AGENTS.md)、ADR-0008、ADR-0040、ADR-0041 的开发边界。根目录 00～10 正式文档保持只读，KubeVirt/CDI 延期，DeepFlow Trace 补全与 PyRCA 维持既有禁用裁决。

## 2. 与现有实现的关系及复用约束

已有资源身份与图、异常检测、Finding/Incident、有限 RCA、指标/日志/网络查询、窗口统计、Fact/QueryResult/Evidence、模型工具调用、多轮会话、持久 Job/Step、租约、预算、取消和界面，均继续复用。

现有 `resource_findings` 已能无 Incident 读取资源最近 50 条 Finding；需要补冻结窗口和引用语义，不另造同名功能。现有固定故障链收集主要围绕网络与资源健康；需要扩展来源和目标类型。既有网络规则与正式 RCA 配方按各自职责继续使用。

为避免产生大量重复或闲置代码，实施必须满足：

1. **收集执行复用同一主路径。** 扩展现有固定收集器及有限计划，不新增队列、调度器、Agent 运行时、模型 HTTP client 或平行来源客户端。不同资源采用有限适用项，不能复制三个完整收集器。
2. **数据保持单一权威来源。** 指标和日志继续由现有后端查询，Finding、执行和 Evidence 继续使用原仓库。先检查已有历史是否足够，只为缺失的健康、关系、事件或变更安全投影增加最小存储；不复制全量指标、日志、配置或资源图。
3. **上下文保存引用与必要派生结果。** 原始正文仍由 Step/QueryResult/Evidence 负责，不在消息、关联上下文和新表中重复保存完整载荷。模型不重复计算统计或执行规则。
4. **规则各有明确职责。** 辅助观察与正式 RCA 分开管理，共用可复用的事实校验和计算。新规则不得复制已有异常检测器，也不建立无实际用例的通用规则插件体系。
5. **新旧协议共享实现。** 新任务采用新合同，旧结果继续可读；兼容层只做必要转换和校验，不长期维持两套完整业务流程。历史已无写入需要的旧分支不得继续成为新任务入口。
6. **替代路径同步收口。** 每个增量说明复用、扩展、替代或新增了什么；对已被替代且确认无调用、无历史读取职责的辅助代码同步移除，不保留无用途的开关、占位接口和未来扩展层。
7. **保留必要的安全与历史代码。** 合同版本读取、权限校验、失败证据、Fixture 和延期能力的 disabled 合同不能仅为减代码量删除。它们与无调用、无保留职责的废弃实现分别处理。

代码规模随实际缺口增长，不预设删除率或新增行数目标。评审以调用路径、事实权威、职责和可维护性判断，不以行数少替代完整功能。

## 3. 功能开发内容

### 3.1 资源异常、事件及历史证据

- 扩展 `resource_findings` 支持冻结窗口和可追溯引用；旧调用继续表示最近记录。历史查询依据 occurrence、事件或归档事实，不能用最新记录的更新时间重建过去。
- 提供有界健康、关系与 Kubernetes 事件历史读取，绑定 UID、来源 revision、事件时间、观察时间及覆盖状态。
- 明确初次 List、Watch 重连、覆盖中断、对象替换和历史缺失；不回填未观察的历史，不以同名资源继承旧身份。
- 补足 Pod 容器异常的安全采集投影：必要运行身份、重启计数、等待/终止原因与时间。排除命令、环境变量、凭据和任意原始消息。
- 新增助手历史的默认保留目标为 30 天，正式 Evidence、法律保留和引用依赖优先。来源更短的保留期继续限制查询，不因此扩建后端历史能力。

### 3.2 通用资源变更证据

- 增加不依赖 Incident 的授权只读变更路径。
- Kubernetes 只保存固定白名单内的实际字段变化、原对象 UID、版本及观察时间。单独的 resourceVersion 变化只表示版本变化，不等同于发布、具体配置修改或精确变更时间。
- 平台执行记录仅提供已授权目标、执行状态、时间及 Post-check 引用。发出命令、命令成功和目标实际变化分别表达，不披露命令正文或输出。
- 变更归属原对象 UID；只有合格历史关系才能关联受影响资源，不把 Deployment 变更改写成 Pod 变更。缺时间或关系证明时保留背景与缺口，不触发 R4 正向判断。

### 3.3 多源确定性收集与关联上下文

- 版本化扩展冻结请求，支持 Pod、Node、PVC，保存目标、显式范围、故障窗、可选等长基线和恢复窗。
- 复用现有 evidence-only 流程，组合适用的健康、Finding、事件、指标、日志、变更和网络证据；HTTP/TCP 只查询合格 Pod 端点对。
- 优先主目标异常及必要反证，再读选中关联资源，最后补可选比较、恢复和日志样例。沿用默认 4 边、上限 8 边及来源预算，不增加超时、内存或权限上限。
- 统计由既有 analytics 计算。样例不当作总量，缺失不补零，基线不可比较时不生成变化结论。
- 上下文只引用同 Job 成功提交的 Step、Fact、QueryResult、Evidence，保存来源、窗口、规则版本、质量与未执行项。
- 取消、预算耗尽、模型失败和接管后保留已提交结果；历史读取重新授权，清理遵守依赖闭包。

### 3.4 有限异常关联与辅助诊断

- Pod：重启、OOM/退出、调度异常，关联同窗指标、日志和原生事件。
- Node：Ready、Pressure、已有资源使用异常及授权范围内的关联影响。
- PVC：Pending/Bound、挂载/附加/供给事件及已有 CSI 诊断证据。
- 网络：复用 HTTP 错误、耗时、TCP 异常和正常链路反证，补两端资源证据。
- 补 R3/R4/R5 的输入路径，保持已有严格谓词。R3 需多个调用方同窗异常、共享关系、共同资源自身异常和合格来源；R4 仅提供有依据的变更关联背景；R5 区分指标改善与完整恢复迹象。

规则有固定版本与稳定顺序。指标较基线上升只表示上升，不自行解释为资源耗尽。日志错误依据合格结构化等级，不凭自由关键词猜测。共现、时间接近和模型判断不确认因果。

新增规则先输出辅助观察。正式 RCA 的谓词、发布和激活继续走原机制，助手解释不改变其状态。

### 3.5 模型解释、自然语言和界面

- 复用模型 Profile、HolmesGPT、官方 MCP 与现有会话，开放新增的有限工具与关联上下文读取。
- 普通自然语言排障沿现有目标澄清、身份确认和范围编辑。模型解释事实并提出检查建议，不能改身份、冻结窗口、统计值或规则结果。
- 保留确定性收集与模型解释独立入口及状态。解释使用绑定原证据的后续轮次，不覆盖原结果。
- 在现有面板增量展示各来源的关联结果；判断可定位原值、窗口、来源、规则和证据，缺口只联动已发布只读检查。
- 旧轮次、未完成、退化和不适用状态分别显示；复用已有多轮、时间冻结、引用、取消、节点与证据定位功能。

## 4. 接口、存储与兼容

- 发布新版收集请求、关联上下文与工具目录，旧 Pod 请求和旧结果保持可读。新任务不得交给不支持合同的旧 Worker。
- 扩展已有 `resource_findings`，补资源变更及历史观察的有界只读工具；复用现有查询和评估入口。
- 模型只选择允许的资源及窗口角色，服务器从冻结轮次取得真实授权与绝对窗口。
- 必要存储使用增量迁移，绑定 tenant、来源 revision、UID、观察时间及证据依赖，不另建配置仓库或图数据库。
- 同步 OpenAPI、Schema、Go、TypeScript、Python 与 provider 校验；历史结果不得因升级而重算、刷新时间或覆盖。
- resourceVersion 不是墙上时钟；采集时间不自动等于事件时间。没有有效证明时继续 unreliable，新增采集本身不提升时间资格。

## 5. 实施顺序与完成标准

按五个增量推进：

1. 来源与历史：安全投影、窗口化 Finding、健康/关系/事件历史及变更。
2. 收集与合同：三类入口、冻结请求、多源流程、持久引用及预算退化。
3. 规则：首批关联观察和 R3/R4/R5 输入闭环。
4. 模型与界面：工具读取、解释、追问补证和关联展示。
5. 开发收口：合同一致性、运行说明、能力开关、兼容回滚及逐项状态。

每个增量先核对现有调用与历史职责，再做必要修改；不得因为方案中出现一个名词就建立新模块。若发现已有实现满足要求，记录复用位置并从新增编码清单删除。

功能完成须满足：

- 三类资源可独立调查，适用证据可关联和定位。
- 核心五条来源有实际可用路径；接口存在、Fixture、跳过或返回 200 不代表来源可用。
- 明确缺什么、为何不能判断及允许的补查；按资格降级不能替代缺失的采集、存储、授权和界面开发。
- 模型离线或解释失败不影响确定性结果读取。
- 新增代码有实际入口和职责，被替代路径有明确收口结果；不存在重复事实权威或长期双轨业务实现。

必要检查覆盖身份替换、窗口边界、Watch 中断、正常反证、仅时间接近的变更、历史缺失、来源撤销、模型失败、取消、预算耗尽、接管及保留清理。功能实现、真实来源、模型中文质量、版本验收分别报告。
