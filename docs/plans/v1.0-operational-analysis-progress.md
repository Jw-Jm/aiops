# V1.0 运行数据关联分析开发记录

2026-10-15。基线 main `53b0b9e91dd32d71d955ec940929952f8434530b`；依据同目录已确认的 `v1.0-operational-analysis-completion.md`。本记录不代表 V1.0 全面验收或生产发布。

## 路径与实现

- 复用原有 Finding occurrence/outbox、analytics 固定模板、Kubernetes informer、资源身份库、Graph/CSI 诊断、Evidence、Job/Step、租约、预算、HolmesGPT 与官方 MCP。异常检测、统计计算和模型调用循环没有另起实现。
- `resource_findings` 的旧无窗口调用继续读取最近记录；新版 `windowRole` 从服务端冻结轮次解析绝对窗口，用不可变 outbox 修订读取 occurrence、状态、来源版本、摘要与 Evidence 引用。不会把最新聚合状态重建成过去状态。
- 新增最小的安全观察索引与覆盖转换记录。健康、容器身份/重启/等待/终止、原生事件及已观察原生关系只在实际采集时保存；未迁移回填现状。首次 List、连续 Watch、重连或覆盖缺口分别表达。事件 UID、事件时间与采集时间分开；resourceVersion 只是版本。
- 通用 `resource_changes` 按白名单比较容器镜像、调度、卷、replicas、owner 等字段；分别返回版本变化、字段变化、历史缺口和实际执行状态/Post-check 摘要。不会复制命令、输出、环境变量、凭据或任意原始消息。Kubernetes 观察时间不升级成可靠变更事件时间；平台执行成功不代表目标实际变化。
- `fault-chain-request/v2` 通过同一固定收集器支持 Pod、Node、PVC。Node 必须显式选择且授权允许集群资源；网络仍只针对同 namespace 内合格 Pod 对。主目标历史/Finding/变更及异常统计优先，随后关联资源、网络与可选指标/日志；预算不足留下未执行项，不增加上限。
- 有限辅助观察覆盖 Pod 重启、OOM/非零退出、等待和调度；Node Ready/Pressure；PVC Pending/Bound 与挂载/供给事件；结构化 error 日志和同口径资源指标变化。正常观察只反驳对应的窄候选。既有 HTTP/TCP 及 R3/R4/R5 谓词保留；补入历史健康、原生关系与已归档 Kubernetes 变更输入，不降低时间、身份、覆盖或归档门禁。
- 收集结果保存成功 Step、Fact、QueryResult、Evidence 的引用与必要派生结果。模型解释使用独立后续轮次；服务端继承同一绑定的故障/基线/恢复窗口。模型不能改窗口、UID、统计或规则。取消、预算耗尽与模型失败仍可读取已提交来源步骤。
- 调查页面增加三类目标、关联支持/反证/缺口/质量、原始安全 Step 定位及下一轮已发布只读工具补查。范围不足提示使用现有范围编辑器，不自动扩权。
- 网络端点的成对复核使用各自不可变快照，不再等待旧流读取的共享映射锁；保留原有 UID/容器寿命、来源授权、前后快照及预算条件。定向并发锁回归和 race 检查通过。
- 将原 HTTP 层 evaluator 的已提交输入装载移到 `investigation.EvaluateCommittedFaultChainTx`，保持同一主路径。原规则、历史 v1 结果与旧目录继续可读，没有保留第二套业务收集器。

## 合同、开关和回滚

新任务使用 `assistant-tools/v2`；MCP 按任务、授权域与目录版本提供独立的官方 SDK server。v1 的工具集合、Finding 与分析参数仍保持旧目录形状。新 Worker 声明 v2；数据库队列策略使旧 Worker 看不到未领取/过期的 v2 任务。升级时仍应排空旧进程后同时更新 API、Go Worker、Python Worker 和 UI，不能把新的 Go heartbeat 当成旧 Python 已升级的证明。

开关继续复用 `AssistantRuntimeConfig.enabled` 与默认关闭的 `faultChainEnabled`，没有额外后台模型调用开关。来源资格仍由原注册、绑定、验证和 qualification 决定。Trace、PyRCA 与虚拟化保持原禁用裁决。

迁移 `00043_resource_observations.sql` 仅前向增加观察/覆盖索引、隔离策略与清理函数。普通目标保留 30 天；已提交来源 Step 保护观察引用，既有 Evidence/法律保留闭包优先。覆盖转换的冻结回执留在原 Step。清理有界并继续使用原 Worker 调度。

Kubernetes 归档写入使用 `kubernetes-projection/v2` 身份，避免新增安全字段与旧 UID/RV 的 v1 归档发生内容冲突；旧归档保持不变。

回滚先关闭固定收集入口并停止接收新 v2 任务，保留已提交数据；使用本版本只读路径继续读取 v2 结果，或待新任务排空后回退进程。不要删除迁移表、法律保留、归档或旧失败记录；旧二进制不能读取全部 v2 合同，不将其当作无损降级。源码发行物料和生产升级/回滚验收仍单独管理。
