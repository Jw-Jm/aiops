## 当前数量

- 22 个菜单页面，458 个设计基准切片。
- 39 个实施任务包，按依赖推进；P0 核实后估时，不按切片张数估算工期。
- 138 项接口操作：62 项现有合同的复用/适配/改造，76 项拟新增操作。
- 现有合同状态表示已在 OpenAPI 核对方法与路径，并有候选代码，不表示本轮完成运行验收。
- 拟新增操作是 P0 合同设计输入；核实底层能力后可以合并或调整，但必须同步清单和切片，不以调整清单为由遗漏功能。

## 清单填写规则

- `slice-map.csv` 的原型路径相对整个 `ops` 项目；`code_targets` 和 `existing_code_candidates` 相对 `platform`。
- 切片主任务按最上层状态和主场景分配，来源模块表示进入该状态的上下文。跨模块入口会出现主任务不同于来源模块的情况。
- `contract_ids` 为待核实的候选接口族，不表示每片都调用该族全部接口；P0 按实际进入步骤精确到请求、方法及字段。
- `visual_status`、`interaction_status`、`api_status`、`persistence_status`、`authorization_status`、`live_status` 六项独立维护，不继承原型通过状态。
- 纯展示/导航可以把确实不适用的后端项标为“不适用”，但须填写理由；不能用它代替未实现的业务操作。
- 验收证据记录实际制品、环境、数据类型、切片、请求/任务标识和截图/日志引用；秘密材料不得写入这些 CSV。

## 只校验本方案

从本目录运行：

```sh
python3 validate-plan.py
```

检查数量、映射、任务依赖无环、已有/拟新增 HTTP 方法与路径、候选代码及相对链接。运行结果写入 `validation.json`，不连接数据库、远程环境或执行浏览器业务测试。

主方案和接口表最终通过本目录自审，业务功能、正式前端像素比对和实际运行仍为后续实施任务。生产发布、KubeVirt/CDI 和完整 Trace 不由本方案恢复。
