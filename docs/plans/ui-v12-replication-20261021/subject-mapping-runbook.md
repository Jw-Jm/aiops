# 原生历史主体映射：r9操作与接续

本轮仅源码、单元、合同及构建验证。55/56均未执行，最后独立验证的任务库为15453/schema54；不是当前在线状态断言。远程不可用时不在本机启动数据库或业务浏览器，不向CodeBuddy派发任务。

## 使用条件与调用路径

由操作人员先核对旧主体真实归属、tenant和既有原生user ID，形成逐项已核对清单。软件只能验证清单结构及其与库内事实的一致性，不能代替人的身份核对。禁止从相同loginName/displayName推导归属，禁止复制旧角色。

路径：外部私有清单 → migration-duty CLI → identity.import_subject_inventory → 不可变清单及同事务审计 → 原生管理员界面 → C-170精确请求再次验证 → 当前会话/版本及有序账号锁 → 清单逐项匹配 → subject_mappings/账号版本/会话撤销/幂等结果/审计同事务 → C-171刷新回显。HTTP管理员没有导入清单权限。

恢复ssh mssc-direct后，先核对已批准主机、任务目录所有权、端口/库和当前版本，再只对任务专属15453库按原迁移流程前滚55/56；禁止对共享库写入、覆盖旧轮次或变更冻结的1～54。保留迁移失败原始日志。没有执行验证前不将本节当作已运行说明。

## 受控导入

使用仓库外的0600普通文件保存连接配置和清单。--input只接受databaseUrl，使用既有专用NOINHERIT、非superuser/非bypassRLS的migration-duty LOGIN，不用API/Worker/超级用户。示意文件（UUID须替换为核对后的真实ID）：

```json
{
  "schemaVersion": "native-subject-inventory/v1",
  "tenantId": "018f0f2b-91c2-7d42-a8dc-f719c5987201",
  "reviewedBy": "已核对操作人员标识",
  "entries": [
    {"legacySubject": "完整历史主体标识", "userId": "018f0f2b-91c2-7d42-a8dc-f719c5987202"}
  ]
}
```

在获准远程机，使用本轮构建的opsctl及私有文件路径：

```sh
opsctl identity import-subject-inventory --input /任务私有目录/migration-connection.json --inventory /任务私有目录/reviewed-subjects.json
```

连接配置、清单内容不得保存到仓库或命令日志。清单1MiB以内、1～1000项，拒绝未知/重复JSON字段、重复旧主体、空UUID。摘要为实际完整清单的JCS规范化SHA256；只改变缩进不会改变摘要。回执仅含tenantId/evidenceDigest/entries/imported。同一清单重放imported=false；已批准旧主体不得通过新清单改派不同目标。

导入要求目标账号属于该tenant、tenant有效、旧主体确实存在于该tenant的旧角色绑定/助手会话/调查Job/执行记录，且不是现有原生主体。当前仅支持这些已核实来源，其他历史来源需补核实；不把来源未知当作已核对。清单正文保存在受限identity表用于逐项验证，不向API公开。

## 界面与失败处理

原生管理员进入“用户与权限 → 历史主体映射”，可分页读取已持久化映射。创建时从当前用户页选真实账号，填写完整旧主体及导入回执摘要，以该用户当前revision和完整请求完成密码/TOTP再次验证。编辑目标/旧主体/摘要后必须重新验证。

成功会新增不可变映射、提升目标账号资料/授权/会话版本、撤销目标会话；原生subject与现有角色/范围不变。操作者映射自己也需要重新登录。409表示版本/既有映射/核对清单冲突，刷新并核对原因后重新操作；不自动覆盖归属。关闭进行中的窗口只中止客户端等待，须刷新确认服务端最终状态。未知提交结果不显示成功。

旧迁移44中已有的映射保留，inventory_digest为空，不自动认定为本轮核对记录，不修改旧审计/业务主体。历史读取权限接入尚未实现：本轮映射不会自动开放历史会话/Job/执行记录访问；后续须对显式归属与当前原生权限范围分别复检，不能使用旧角色回退。
