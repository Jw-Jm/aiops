# r30 截图安全策略（返修后）

## 规则

1. 任何截图都不得包含因子秘密：otpauth 登记 URI 及其 base32 密钥、恢复码（`XXXX-XXXX`）、动态码（6 位）或填入非密码框的密钥。
2. `safe-capture.mjs` 在每次截图前逐项探测页面文本与非密码输入框，命中即**拒绝截图**并抛错。因此：
   - 「待绑定密钥可见」「恢复码仅显示一次」这类状态**不产出图片**，只用 `describeSecretState()` 记录可机检的状态（是否出现 URI、恢复码数量、是否有动态码填入），并写入对应 run JSON。
   - 只有密钥已从页面移除的真实状态才截图：刷新后的已启用态、取消绑定后、闲置/绝对到期后、管理员重置后的强制重绑态。
3. 遮罩只允许用于**非秘密**区域的视觉对照；秘密区域不允许用遮罩"补一张通过图"。当前 r30 没有使用任何遮罩截图。
4. 秘密值本身只存在于远程任务根 `private/`（目录 700、文件 600），不写入仓库、日志、报告或对话；run JSON 只保留 revision/challengeId/requestId/状态。
5. 一旦发现有图片可能包含秘密，进入隔离（旧任务 `private-evidence-quarantine`，目录 700/文件 600，`quarantine.json` 记录清单），不得复制回 Git，也不得再次展示；同时必须通过既有原生受控机制（管理员 MFA 重置）使该身份的因子与恢复码失效，并保留前后只读核对。
