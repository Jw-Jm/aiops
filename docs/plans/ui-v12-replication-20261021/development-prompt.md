四、后端和关键业务约束

优先复用已有服务、数据库、Job、Worker、权限和审计链路；补齐功能必须贯通正式调用路径。不得以固定成功响应、浏览器定时器、内存数组或演示数据代替真实业务。Fixture 仅用于隔离的视觉及自动化测试，不进入正式业务构建或冒充真实来源验收。

内置账号：不保留面向用户的 OIDC/Keycloak 登录选项。完成账号、密码、首次设密、服务端会话、退出及撤销、用户管理、授权和必要的再次验证，并同步 Web、API、Worker、CLI、安装及运行配置。显式映射旧主体与新 user_id，保留历史权限归属、审计和证据，不按同名账号自动授予权限。保留组织隔离、CSRF、防越权及高风险操作绑定；保留工作负载认证链路。不得以浏览器密码判断或勾选确认代替后端认证。

模型配置：保持服务地址、模型 ID、访问凭据、上下文长度四项面向用户的配置。能识别时自动读取上下文，手工值不得扩大模型真实能力。复用既有模型接入及 HolmesGPT/官方 MCP/任务链路，不另建 Agent 循环；API 与 Worker 使用一致的已准入配置。连通、准入、可执行任务和回答质量分别判断，不伪造准入材料、不取消安全门禁。未知模型或不兼容地址应明确失败或待处理；超出当前模型合同的变化先记录具体裁决。

多集群：查询、对话、告警、调查、命令、巡检及配置都要正确传递集群和权限范围；切换后清理失效选择并隔离缓存，不混入其他集群数据。来源注册、访问授权、组件存在、来源合格、数据可用和业务健康分别呈现。新集群检查默认只读，无权限不能判定为缺失；组件安装须使用明确授权和合格安装材料，不接管、覆盖或重装已有第三方组件。

命令与巡检：保留风险判断、审批或再次验证、任务状态、输出、证据和执行后检查。现有 command-executions 创建接口不代表已有全局列表；现有 GET post-check 只读固定报告，新检查不得覆盖旧报告或重新执行命令。巡检调度在服务端持久化并保证任务时段幂等，暂停计划不等于取消运行任务。不得用前端计时器模拟调度。

AI、观测、告警与知识：复用真实查询及流式协议，处理断流、取消、超时、重试、过期和引用失效。历史会话支持规定的删除/归档语义；当前与历史告警明确区分。结构化结果、证据引用及知识发布版本可追溯，归档不能破坏旧证据。通知重试保留每次尝试和不确定回执，测试限于隔离接收端；不作无法证明的跨系统“只发送一次”承诺。
